# StreamElements Issues

This is where you report bugs and request features for StreamElements.

Anyone with a GitHub account can open an issue here. We read every one. When you file something, you get a public thread that we update as the work moves — so you can see what happened to your report instead of wondering.

## Before you open an issue

- **Search first.** Someone may have already reported it. Add a 👍 or a comment to an existing issue rather than opening a duplicate — it helps us gauge how many people are hit.
- **Pick the right place.** This repo is for bugs and feature requests in the product. For account, billing, payout, or "how do I…" questions, use [Support](https://support.streamelements.com) instead. Those get answered faster there, and they don't belong in a public tracker.
- **Don't post private information.** Issues here are public. Never paste passwords, tokens, API keys, email addresses, or anything else you wouldn't want the whole internet to read.

## How to report

Open a [new issue](../../issues/new/choose) and pick a template:

- **Bug report** — something is broken or behaves wrong.
- **Feature request** — something you'd like us to build or change.

The templates ask for the details we need to act. The more you give us up front, the less back-and-forth it takes.

## What happens next

1. You file an issue.
2. We triage it — usually within a few working days — and pull it into our internal tracker.
3. The GitHub thread stays in sync: as the status changes, this issue is updated and closed when the work ships or the request is resolved.

You'll get a notification at each step, so you don't have to check back.

## Security

Do **not** open a public issue for security problems. See [SECURITY.md](SECURITY.md) for how to report them privately.

## A note on responses

We can't promise a timeline on any single report, and not every feature request gets built. But every issue is read, and you'll always be able to see where yours stands.
